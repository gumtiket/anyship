# Claude에 전달할 STRONG/FAST 모델 선택 프롬프트

아래 내용의 판단과 비교표만 작성해줘. 코드·IAM·리전 설정은 변경하지 마.

## 프로젝트와 현재 상황

Team Bronze는 FastAPI 저장소를 진단하고 변경안과 공통 배포 명세를 만드는 AI 파트를 개발 중이다. 12-factor 위반과 배포 세트는 규칙이 판정하며 LLM은 설명·근거·제한된 코드 변경안·실패 복구안을 생성한다.

- STRONG: 코드 변경안, 실패 원인 분석과 복구 diff.
- FAST: 진단 설명, 세트 추천 근거와 간단한 분류.
- 현재 코드 입력은 정적으로 읽고 마스킹한 요약이며 기본 총 20,000자 제한이다. 모델의 긴 컨텍스트만으로 미수집 코드를 분석할 수 있다고 주장하지 마라.
- 실제 호출에 성공한 임시 조합은 Sonnet 4.6 / Haiku 4.5다. 실제 STRONG 코드 생성 품질을 확인한 것은 아니다.
- Sonnet 5.5 / Haiku 5.5는 계정 접근 제한이 있었고 해제 여부는 미확인이다.
- 팀원은 미국 리전에서 OpenAI GPT-5.6 계열을 사용할 수 있다고 알려줬다.
- 현재 클라이언트는 boto3의 Bedrock Converse다. 기본 maxTokens=4096이며 보통 temperature=0을 보낸다. Sonnet 5.5/Haiku 5.5는 sampling 옵션을 생략하고 모델별 thinking/effort 옵션을 따로 보낸다.
- pydantic v2로 JSON을 검증하고 JSON 재요청은 최대 2회다. 토큰 제한/거절/응답 없는 timeout은 자동으로 모델을 다시 호출하지 않는다.
- 기본 테스트는 Fake로 실행한다. 사용자 코드·DB는 수정하지 않으며 자체 샘플 두 개만 Docker/임시 Postgres로 검증한다.
- P6는 현재 모델 조합으로 진행한다. 버전 선택 때문에 P6와 서비스 연결을 중단시키지 않는다.

## 검토 대상

Sonnet 4.6·5.5, Haiku 4.5·5.5, GPT-5.6 Sol·Terra·Luna.

## 요구사항

1. AWS와 각 모델 제공자의 최신 공식 문서를 확인하고 출처·확인 날짜를 붙여라. 모델명은 요청한 이름 그대로 비교하라.
2. 제공 여부, 리전/추론 프로필/엔드포인트, 실제 계정 접근 가능 여부를 구분하라. 계정 접근은 추측하지 마라. 미국 리전과 서울에서 가능한 호출 경로를 구분하라.
3. Converse 지원, 요청 옵션, JSON 출력, 추론 토큰과 출력 예산, 지연·비용을 비교하라. OpenAI 직접 API 가격을 Bedrock 가격으로 대체하지 마라.
4. 모델 ID 변경만으로 되는지, 클라이언트 수정/IAM 변경/리전 변경이 필요한지 구분하라. 특히 기본 temperature=0과 추론 옵션의 호환성을 확인하라.
5. STRONG/FAST 추천 조합 1개와 대안 1개를 제시하되, 우리 작업에서 미검증한 성능은 가설로 표시하라.
6. 같은 샘플과 의도한 실패 사례를 사용해 JSON 성공률, 설명의 사실 정확성, diff 적용·게이트 통과, 시간·비용을 비교하는 작은 검증안을 제시하라. 기록 응답의 replay나 고정 샘플 회귀를 독립적인 모델 품질 평가라고 부르지 마라.
7. 현재 성공한 경로를 유지하면서 비교할 방법을 우선하고, 결과가 없으면 선택을 보류할 조건도 적어라.

계정 ID·인증 정보는 요청하거나 보고서에 넣지 마라. 확인할 수 없는 가격·접근 권한·실제 성능은 미확인으로 남겨라.

최종 출력: 추천 판단 3~5문장, 비교표, 남은 확인 3개, 최소 실험안.
