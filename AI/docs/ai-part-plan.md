# B 파트 (AI) 작업 분해와 기록

> 작성: 2026-10-07 (수) 밤 / 기준 문서: 설계 문서 + MVP 문서
> 담당: B (AI) / 협업: A(서비스), C(인프라)

## 0. 원칙

- **독립 개발 → 나중에 합치기.** B는 서비스(A)나 인프라(C) 없이 **CLI 하나로 끝까지 돌아가게** 만든다.
- **파일 기반 계약.** 입력은 레포 경로, 출력은 `out/` 폴더의 파일들. A가 나중에 이 CLI(또는 함수)를 그대로 호출한다.
- **결정적인 부분은 규칙으로, 설명은 LLM으로.** 세트 판정(스케줄러·웹소켓 import 탐지)은 규칙, AI는 근거 문장 담당. LLM 호출은 `temperature=0`, 출력은 스키마로 검증한다.
- **데모 경로는 결과를 캐시.** 샘플 앱 2개의 AI 결과를 저장해 두고, 실패 시 사전 결과로 대체할 수 있게 한다.

## 1. B의 입출력 계약

```
입력:  repo_path (클론된 레포 디렉터리), target_env (aws | onprem), log 콜백
출력:  out/
        ├─ diagnosis.json      # 12-factor 위반 목록, 지원 등급
        ├─ changes.diff        # 코드 변환 diff
        ├─ Dockerfile
        ├─ deploy-spec.yaml    # 배포 명세 (스키마 검증 통과)
        ├─ recommendation.json # 세트 이름, 근거, 예상 비용, tfvars
        ├─ gate-report.json    # 검증 게이트 결과 (원본 실패 / 변환 후 통과 로그)
        └─ cost.json           # 단계별 토큰 사용량과 비용
```

진행 로그는 `log(stage, message)` 콜백으로 내보낸다 (A의 SSE 연결용). 단계 이름은 A와 합의한 상태 목록을 따른다: 분석 중 → 검증 중 → (PR 대기).

## 6. 위험과 대비

| 위험 | 대비 |
| --- | --- |
| Bedrock 접근 막힘 (서울 리전, 모델 허용) | 수 밤에 호출 한 번 테스트. 막히면 교차 리전 추론이나 다른 리전 |
| LLM이 만든 diff가 적용되지 않음 | `git apply --check`로 먼저 검증, 실패 시 오류를 넣어 재생성. 샘플 앱 기준으로 프롬프트 튜닝 |
| 명세 YAML이 스키마에 안 맞음 | JSON Schema 검증 + 재시도. 필드 값이 규칙으로 정해지는 부분(포트, healthcheck 등)은 LLM이 아닌 코드가 채움 |
| 스케줄러를 LLM이 못 찾아 세트 선택 장면이 무너짐 | B2 규칙이 판정, LLM은 근거만 작성 |
| 검증 게이트에서 사용자 코드가 소켓·시크릿에 접근 | B9b 체크리스트로 코드 리뷰, 환경변수는 명시한 것만 전달 |
| 게이트 컨테이너가 내부 네트워크라 포트 publish 불가 | 같은 네트워크에 curl 컨테이너를 띄워 헬스체크, curl 이미지는 사전 pull |
| 데모 중 AI 호출 지연·실패 | `demo-cache/`의 사전 결과로 대체, 발표에서 밝힘 |
| LLM 결과가 실행마다 달라 재현이 안 됨 | `temperature=0`, 프롬프트·출력 저장, 골든 테스트 |
